How it works guide

Every prototype, demo, challenge and showcase opens with a short guide, its standard talk track: what it does, how it works and how to present it. Someone who only gets the link still understands it.

How the prototype works

Shows the 128 invoices the agent couldn't match

Atlas is a sample prototype. Every morning an agent matches supplier invoices to their orders and leaves the rest for a person, who works through them on this page.

This morning's run
Invoices checked470
Matched by the agent342 (72.8 %)
Left for a person128

Three figures show what the agent took off your desk

The agent compares each invoice with its purchase order and matches it, or leaves it here for a person with a reason. The three figures at the top say how this morning went.

Key figures

Three reasons send an invoice to a person

The agent compares each invoice with its purchase order. When the price, the quantity or the order itself doesn't match, the invoice lands here with that reason.

Reasons
Price mismatchThe invoice charges more than the order agreed.
QuantityThe invoice bills a different quantity than the order.
Missing PONo purchase order matches the invoice.

Show it in five minutes

Four steps, five minutes in all. Start on the exception list.

  1. Open the exception list. “Each morning the agent leaves only these for a person.” 1 min
  2. Read the lilac banner. “Lilac marks what the agent did: it matched 342 invoices without help.” 1 min
  3. Filter by Price mismatch. “Here a person decides whether a price difference is acceptable.” 1 min
  4. Open New rule. “A rule lets the agent settle this kind of difference by itself next time.” 2 min

Title

The title says what kind of thing the guide explains. The words are fixed, so every guide is recognisable at a glance.

Guide titles
KindEnglishGerman
PrototypeHow the prototype worksSo funktioniert der Prototyp
DemoHow the demo worksSo funktioniert die Demo
ChallengeHow the challenge worksSo funktioniert die Challenge
ShowcaseHow the showcase worksSo funktioniert der Showcase

The header button that reopens the guide reads “How it works” (“So funktioniert's” in German), with the info icon and visible text. Pages that are none of these four kinds, such as the personal site, these docs and the landing starter, have no guide.

Chapters

A guide has three to eight chapters, and four to six read best. The first two and the last are fixed; the chapters between them are yours. Each chapter has a short label in the rail, the list of chapters beside the content.

Chapter order
PositionChapter idRail labelAnswers
FirstwhatWhat it doesWhat it is, who it is for and which question it answers
SecondhowHow it worksInputs, logic and outputs, and the key figures: a table with one row per figure, what it measures and its value. See Key figures
BetweenYour ownUp to five wordsOptional: what is simulated and what is real, results, how to read the page, limits. “How” can run over several chapters.
LastpresentHow to presentThe presenter's path, described under The presenting chapter

Copy rules

  • The heading is one claim in sentence case, at most 60 characters, and specific to the product: a number or a noun from the prototype. No questions and no colon kickers.
  • The lead is one or two sentences, at most 40 words.
  • The body is one figure, table or short list of at most five items.
  • Numbers come from the prototype's own data. An app that computes its figures fills them in when it receives vc:guidechange.
  • No eyebrow and no “Chapter 2 of 5” label: the rail and the footer already say where you are.
  • Plain words in British English or German, following the Writing rules.

Guide attributes
AttributeOnDoes

From a script, Vici.guide.open('guide', 'present') opens a guide at a chapter and Vici.guide.show('guide', 2) moves an open guide to another one. The dialog fires vc:guidechange with the chapter's id and index, and vc:guideclose with its returnValue.

Two languages

A prototype with an EN | DE switch carries one guide per language, each written out in full. The check accepts such a page when every guide follows the whole standard and these rules hold:

  • Each dialog has its own id and says its language in lang, and no two share one. Its title is in that language.
  • Each guide has data-vc-guide-auto and its own header button. The page shows only the button of the language on screen.
  • A key figure carries its name in each language: data-vc-kpi in English and data-vc-kpi-de in German. Each guide's How it works chapter gives it a row under the name in its own language.
  • A plain script at the end of the body, which runs before the deferred vici.js, takes data-vc-guide-auto off the other language's guide, so the guide that opens by itself is in the page's language.
  • The two guides are one guide in two languages, so it opens once per tab, whichever language the visitor switches to: the script notes the page's guide as seen once the other one has opened (see Opening).

<dialog class="vc-dialog vc-guide" id="guide-en" lang="en-GB" data-vc-guide data-vc-guide-auto …>…</dialog>

// js/lang.js: lang is the page's language (?lang=, then the visitor's last choice, else English)
['en', 'de'].forEach(function (l) {
  if (l !== lang) document.getElementById('guide-' + l).removeAttribute('data-vc-guide-auto');
  document.querySelector('[data-vc-guide-open="guide-' + l + '"]').hidden = l !== lang;
});
var seen = function (l) { return 'vc-guide:' + location.pathname + '#guide-' + l; };
try {
  if (sessionStorage.getItem(seen(lang === 'de' ? 'en' : 'de'))) sessionStorage.setItem(seen(lang), '1');
} catch (e) { /* storage blocked: the guide opens */ }

The switch itself shows the other button and leaves the open state alone. Duty Radar, Victor's bureaucracy relief prototype, works this way.

Behaviour

  • The guide is a modal dialog: Escape and the close button close it, focus stays inside, and closing returns focus to whatever opened it.
  • When it opens, focus goes to Next. On every change of chapter, focus moves to the new chapter's heading, so a screen reader reads each chapter once. There is no live region.
  • From 900 px the rail lists the chapters with numbers in hexagons. Below that it shrinks to a strip of numbers, and at 600 px and below the guide fills the screen.
  • The rail's items are buttons, and the current one has aria-current="step".
  • The footer shows the count in tabular figures, Back, which is disabled on the first chapter, and Next. On the last chapter Next closes the guide.
  • Chapters change without animation, and the hexagon markers keep their outlines in Windows contrast themes.

Opening

  • With data-vc-guide-auto, the guide opens by itself the first time a prototype loads in a browser tab, and not again when that tab reloads. vici.js notes it in the tab's session storage under vc-guide:, the page's path, # and the guide's id. If the browser blocks storage, it opens on every load.
  • ?guide=0 in the address keeps it closed, for a presenter who has already explained the prototype.
  • ?guide=present opens it at the presenting chapter. Any chapter id or number works the same way.
  • The header button reopens it at the first chapter.

The presenting chapter

The last chapter is a script for whoever shows the prototype, Victor or anyone he sends the link to.

  • It holds three to seven steps in an ol.vc-guide__path.
  • Each step names the control or view to show, in bold, then one sentence to say, in quotation marks, then its time in .vc-guide__time, such as “1 min”.
  • When the sentence holds markup, such as figures a script fills in, it goes in one span.vc-guide__say, so the path keeps it whole.
  • The lead gives the total time, and the steps add up to it.
  • If the prototype has a demo script, this chapter condenses it.
  • The last button closes the guide, so the page behind it should already show the first step. Its label comes from data-vc-guide-done.

Key figures

A prototype shows two to four key figures at the top of the page, usually top right, so a customer sees at once what the case delivers: money gained, lost or saved, lead time, time from detection to decision, session cost (measured in a live run, estimated in a simulated one), people affected, performance against a benchmark or a score. Each is a vc-stat tile that carries its name in data-vc-kpi, and on a page in two languages its German name in data-vc-kpi-de as well. Build a prototype has an example of each.

  • The How it works chapter explains every key figure in a table, one row each: the figure's name as on its tile, what it measures and its value. Where the numbers come from and what is simulated go in a chapter of their own, such as “What is real”.
  • The presenting path points at the figures when they move, so the talk track says what each one shows.
  • The figures answer first: before anything runs, they show what the case puts at stake, such as “€10,293 at stake a year”, rather than a row of zeros. Where only a run can compute them, the page runs the case once in the background. A figure that counts what the run does starts from a value that makes sense, such as “0 of 23”. Name each figure for what it shows on the first screen: a tile called “Cost avoided” reads zero until something is avoided.
  • A figure computed from part of the data says so in its value, not only in its note, so nobody reads it as final: “77 on 5 of 6 layers”, “4 of 12 checked”. A figure that needs all the data shows “…” until it is in, and its note says what it waits for.
  • When a decision moves a figure, the tile keeps its old value, struck through in s.vc-stat__was before the new one, so the room sees the change happen. The note says what moved it. See Stat card.

Presenting step by step

A prototype that tells a story in steps lets the presenter set the pace, and runs by itself for a visitor alone. The Data Quality Agent shows the pattern: the start and five steps, one screen each, with four key figures top right.

  • The steps sit in a vc-stepper bar between Back and Next. A click on a step, the arrow keys and a presentation clicker, which sends the arrow keys, move between them. A step the run has not reached is disabled.
  • Each step shows at once, or plays out in seconds as the agent works and stops where the room should talk, saying so in the bar, as in Navigator; a click on a step or a link always shows it at once. A simulated run goes as far as it can and waits only where a person acts or the room should talk; a slow timed replay leaves the room watching a progress bar.
  • Where the story runs on between two steps, as Repack Pilot's night does from one clock time to the next, Play counts that stretch in the step's reading time: it holds the step's moment for at least four seconds, then plays on to the next step and opens it, so the walk keeps one pace and stops only where a person acts.
  • Where every step shows at once, Play walks them, as in the Price Variance Agent. Play, Pause and Replay share one button before the vc-stepper. Play starts when the guide closes, or with the start button where the first screen waits for the person to start the run; it stays on each step for as long as its title and lead take to read, 7 to 14 seconds, holds while a dialog or a menu is open and stops wherever a person acts. Under the story, the bar says when the page moves on, a bar along Next's foot fills as the step is read, and --vc-step-fill (0 to 1) on the current vc-step fills the rail to the next step. Space plays or pauses; a step chosen by click, key, clicker (the arrow keys, PageDown and PageUp) or link pauses it. Once the person has done the last step's action, the story is over: Play ends at once and its button offers Replay, as the bar under the story does, rather than a Pause beside a bar that says Done. Until then Play holds, on the last step too: where one decision brings the next, such as a lever and then its draft, it waits for the draft rather than ending in between.
  • Where a person acts, the step says so in the bar, such as “Your decision”, and its marker turns merlot. Next cannot pass an open decision.
  • Whatever the page waits for, it asks for where the eye is: a bar right under what just happened says in words what to do next, such as “Your move” or “Your decision”, and holds the one primary action, which draws attention until it is pressed. Its sentence says what pressing the action changes, in the visitor's words rather than the data's: Repack Pilot's bar says “Confirm the agent's entry and the world model knows this barcode from now on”, where the button alone says “Confirm entry”. The bar stays in view however long the step grows, and it never covers what it asks about: where the page asks for a decision, every option, doing nothing included, shows in full above the bar at 1280 × 720. A Next button alone is easily overlooked, and a visitor without a presenter won't know they have to press it. A first screen that waits for the person to start the run is their turn like any other: its “Your turn” bar holds the start button as the one primary action.
  • Where the run starts by itself when the guide closes, the button for a live run with a model says so, such as “Run it live”, and stands after the steps with the AI notice beside it, as in Navigator. A Start button before the steps invites a visitor to start what is already running.
  • Where the action is part of the work area, such as one of several options or drafts, a merlot vc-callout headed “Your turn” stands right above it and says in one sentence what to do, and Next steps aside until the person has acted.
  • The primary action names where it leads, such as “Next: find the cause”, so a visitor knows what pressing it shows; the bar's own Next stays secondary. vc-attention draws the eye to it: a merlot ring pulses out three times, then rests as a soft frame until the button is pressed; under reduced motion only the frame shows. Where the page waits for the person, the ring starts at once; on a step that Play has paused, after a few seconds without a click or a key.
  • Each step answers one question in its title, in plain words and with its figure: “Paying early cost €3,482 last year”.
  • The address follows the presenter, such as ?case=early-pay&step=4, so a link opens the same screen. A link to a later step plays the run up to it.
  • Each step change moves the focus to the step's title, so a screen reader announces it. A title that only a screen reader sees stays hidden while it has the focus, so the buttons under the pointer do not move.

The key figures move with the story. They show the stake from the first screen; the decision strikes the old value through and shows the result beside it, such as €10,293 becoming €0 left a year, and a clock that runs from detection to decision stops there. Its note then says so, such as “stopped at your decision”: “until your decision” reads as a countdown.

The talk track quotes the figures on screen, never a copy of them. Each figure in the presenting chapter is a span with a data-fig name that the page fills from the same results its tiles show, so the script cannot drift from the demo. It says a figure as its tile does, with the part of the data it rests on: “77 on 5 of 6 layers”, not “77 of 100”.

Check

npm run check reads the guides of the app, dashboard and blank starters and fails when one breaks these rules: the title, the order and number of chapters, one heading, lead and body in each, the length limits, a path of three to seven timed steps with a sentence to say, a header button with visible text, and a How it works chapter with a row for every key figure marked data-vc-kpi, saying what it measures and its value. A page in two languages passes with one guide per language that keeps the rules under Two languages. npm run check:render opens each starter in a browser and tests the behaviour and opening rules above.

A prototype checks its own guide the same way. guideProblems(html) from scripts/lib/guide.mjs returns the rules a page breaks, none when it follows them, and node scripts/check-guide-render.mjs http://localhost:8000/ runs the browser test against a prototype served over http.
