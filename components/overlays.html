Overlays

Everything that floats above the page is built on the platform: <dialog> for modal work, the Popover API for menus. Focus handling, the Esc key and the top layer come from the browser. vici.js only adds open and close triggers and positioning.

Dialog

A modal dialog interrupts the flow for a decision or a short task. Open it with data-vc-open="id", or with dialog.showModal() in your own script. Close it with any element that has data-vc-close, with Esc, or by clicking the backdrop.

Sizes: --sm (25rem), default (34rem), --lg (50rem). In destructive dialogs, put autofocus on the safe choice. Add data-vc-dismissable="false" to stop the backdrop from closing it.

A body that holds only text and scrolls, such as a method or a glossary, takes the keyboard's focus so the arrow keys can scroll it: Chromium makes such a box focusable. Its focus ring sits just inside its edge, where the dialog doesn't cut it off, and the guide's rail and chapters do the same. With reduced motion the dialog and its backdrop appear without moving. scripts/check-dialog-render.mjs, part of the render checks, opens a dialog with reduced motion and fails when anything moves, and Tabs into a scrolling body and fails when its ring doesn't show along its side.

Live-run dialog

A prototype that can run live opens this dialog before the first request: the person hands over their own API key, chooses how thorough the run is and how much it may spend, promises to enter public information only and starts the run. Its parts come in this order, so a person who has met one live prototype finds their way in the next.

  1. The key goes in a password field with a show button. The note under it says where the key stays (in this tab's memory, gone on close or reload) and links to where keys come from. A key the page already holds shows masked, such as sk-ant-…9fQx, with Forget key beside it.
  2. The setting is a segmented control with the cheaper default chosen.
  3. Research and Advanced follow where a prototype has them. Research is a switch, off, with what it adds to the cost; Advanced is closed and holds the model and the effort.
  4. The budget cap for this run is a slider with its value in words beside it.
  5. In the acknowledgement the person promises to enter public information only. It is unticked at every opening.
  6. The estimate gives cost and time with these settings and is announced as they change.
  7. The start button sits in the footer, disabled until the key looks right and the box is ticked, with “You are interacting with an AI system” in a lilac tag beside it.

Where the page finds what is usually private in what the person entered, such as an e-mail address or the word “confidential”, a warning lists it above the footer and asks them to remove it or confirm it is public. It warns; it does not block.

From 1280 × 720 to 1920 × 1080 every part shows without scrolling, the estimate too: up to 880 px of height the dialog takes up to 94 % of the window and its parts sit 8 px apart; above it a dialog's 85 % holds them. When a warning appears, the body scrolls and the footer stays, so the start button and the notice remain in view. scripts/check-live-fit.mjs, part of the render checks, opens the demo with no warning at 1280 × 720, 1366 × 768, 1440 × 900 and 1920 × 1080 and at every height from 720 to 1080 px, and fails when the body has to scroll.

Type any test value and tick the box, and the start button turns on; it starts nothing here. The value lives in a variable of this page's script, so a reload forgets it. Never type a real key into a demo.

Keep the key in one variable of one module, as Nothing is kept sets out, and check it with the provider's free call before the run, such as listing the models. The field sits in no <form>, carries autocomplete="off", spellcheck="false", data-1p-ignore and data-lpignore="true", and the dialog refuses to work inside another page's frame. The start button stays disabled until the key looks right and the box is ticked, and the box is unticked every time the dialog opens. liveDialogProblems(html) from scripts/lib/live.mjs checks the parts, their order, the key field, the setting, the cap, the box, the estimate and the notice beside the start button, with a self-test of planted mistakes.

Menu

A menu is a list of actions in a popover. The browser handles light dismiss (click outside, Esc) and the top layer. vici.js places it under its trigger, moves focus into it, adds arrow-key navigation and returns focus when it closes.

Tooltip

A tooltip names a control or adds a short hint. It appears on hover and on keyboard focus, and hides with Esc. When it is the only name of an icon button, connect it with aria-labelledby. When it adds information, use aria-describedby. Never put essential or interactive content in a tooltip.
