Built in cells, not circles.

Vici is the design system behind Victor Pflüger's prototypes, websites and data products: one stylesheet with a deep merlot base and soft pastels, and a hexagon wherever you would expect a circle.

What's new in Vici 2.0

These changes are on main, so the docs and the stylesheet already use them; the version number stays 1.0.0 until the 2.0.0 release. Each item links to where you can see it.

Two new pages

  • Writing, in Guidelines, covers voice, headings and labels, numbers and units, punctuation, German, and the patterns Vici doesn't use, with the stock words the build rejects.
  • How it works guide, in Components, sets the short guide every prototype, demo, challenge and showcase opens with. You can open its English and German examples there.

Four new principles

  • Every surface is signed, so every prototype, demo and website ends with the byline, the personal site included.
  • Every prototype explains itself with a How it works guide.
  • Every prototype shows what it is worth with two to four key figures at the top, each explained by its guide.
  • Every live run says it is an AI: “You are interacting with an AI system” wherever a prototype can start a live run with a model, and nothing leaves without a person's approval.
  • The five earlier principles keep their meaning and lose their numbers, and Accessible by default now names WCAG 2.2 AA as the floor.

The guide component

  • vc-guide is a dialog with one section per chapter, a list of chapters beside them, a presenting path with times, and Back and Next. See its content format.
  • It opens by itself once per browser tab; ?guide=0 keeps it closed and ?guide=present opens the presenting chapter. See Opening.
  • vici.js runs it: data-vc-guide-open on any button, Vici.guide.open() and Vici.guide.show() from a script, and the events vc:guidechange and vc:guideclose. Vici.version now reports the release.
  • Focus moves to each chapter's heading, so a screen reader reads every chapter once. After a mouse click the heading shows no focus ring; with the keyboard it does. See Behaviour.
  • Steps in a stepper can now be buttons, vc-step__button, as in the guide's list of chapters.
  • vc-guide__say holds a sentence to say that contains markup, such as figures a script fills in. See The presenting chapter.
  • Key figures are vc-stat tiles marked with data-vc-kpi. The How it works chapter gives each one a table row with what it measures and its value, and the check fails when one has none. See Key figures.

The byline

  • It ends every page, this one included: “Built by”, the portrait and name linking to LinkedIn, and now a globe linking to the website, with the tooltip “Website”. See Byline and profile links, the page that was called Profile links.
  • The personal site carries it as well; its own profile links keep rel="me". See On the personal site.
  • The addresses live in one file, profile.json in src/brand. The build writes them into the docs, the starters and the Streamlit helper.

22 new icons

They were drawn for the prototypes on the same 24 px grid, with hexagon round forms, and bring the set to . The translate concept is called swap. Select one to copy its class, or see them all on Icons.

Retired

  • .vc-eyebrow, the small capitalised label over a heading, is gone. Use nothing, or a caption after the heading; see Patterns Vici doesn't use.
  • .vc-bg-aurora and the tokens --vc-aurora-1, --vc-aurora-2 and --vc-aurora-3, the blurred gradient wash, are gone. Use a flat pastel ground, as Colour describes.

Rules on other pages

  • Colour keeps status colours apart and asks for flat pastel grounds instead of gradients.
  • Typography says when capitals are allowed.
  • Hexagon says cells carry meaning, and keeps the honeycomb for real content.
  • Accessibility covers the guide's keyboard pattern, the byline's targets and the page language.
  • Data visualisation and Elevation show their palettes and surface levels as tables.
  • Logo and Getting started lose their numbered headings, and Getting started lists what Vici leaves out in a table.
  • Layout and spacing no longer lists the retired utilities.

Starters

  • The app, dashboard and blank starters open with a How it works guide and end with the byline; the app and dashboard mark their key figures.
  • The landing starter lost its gradient and eyebrows and ends with the byline. It will be rebuilt for 2.0.

Checks

  • npm run check now also checks every byline, the guides in the starters, the Writing rules on every page and the distance between status colours, and it is stricter about anything round. See what the guide check covers.
  • npm run check:render opens each starter in a browser and tests its guide.
  • A prototype can import the same checks: guideProblems(), bylineProblems(), writingProblems() and aiNoticeProblems().
  • The new files are check-byline.mjs, check-guide.mjs, check-guide-render.mjs and check-ai.mjs in scripts; byline.mjs, guide.mjs, writing.mjs, ai.mjs and separation.mjs in scripts/lib; profile.json and banned-words.json as data.
  • GitHub Actions runs npm run check and npm run check:render on every push and pull request.

Across the site

  • Every page is marked as British English with lang="en-GB", keeps a no-break space between a number and its unit or %, and has no em dashes in its text.
  • The small section label above each page title is gone. On these pages that, or a one-line fix, was the only change: Actions, Content, Data display, Feedback, Forms, Navigation, Overlays, Motion, Integrations, Licence, Starters, Theming and Tokens.
  • The sidebar lists Writing after Principles and How it works guide at the end of Components.
