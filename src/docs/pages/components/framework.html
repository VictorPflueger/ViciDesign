Framework view

A strategy framework laid out as areas, with what a team wrote in each. When agents complete, challenge and answer it, every item shows its state with a mark and a word, never with colour alone.

Areas and items

.vc-framework is a grid of .vc-framework__area sections. Each area has a title, the question it answers and a list of items. Two columns suit a SWOT, .vc-framework--3 a PESTEL; a canvas sets its own grid-template-areas on the grid. An area with nothing in it yet shows its question and a .vc-framework__empty line instead of a blank box.

An item is a details element. Its summary shows the mark, the text and the state words; opened, it shows the whole text and its notes, such as where an AI item comes from and how sure the agent is. No script is needed, and the keyboard opens it like any other details.

States

An item has a source and, once challenged or answered, a status. Its mark shows the status if there is one, otherwise the source; its words name both. Lilac marks what the AI wrote, coral what the challenge questions, sage what a chosen answer addresses.

Pointing at items

When a card elsewhere on the screen is selected, such as an issue or a strategy, set aria-current="true" on the items it concerns, or on a whole area. They take the accent outline, so the room sees which items the card is about.

Tight spaces

At 1280 × 720 a framework of four areas leaves little height for each item. .vc-framework--compact shows every closed item's first line only; opening it shows the rest. The state words stay visible either way.

Check it

frameworkProblems(html) from scripts/lib/framework.mjs returns an empty list when every item has a mark and a state word, every item the AI wrote or the challenge added says so, every challenged item names its fault, and every area has a title. Prototypes run it on each screen's markup; npm run check runs it with a self-test on this page.
