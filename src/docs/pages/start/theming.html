Theming

Vici ships a light and a dark theme built from the same tokens. Components never use raw colours. They read semantic custom properties such as --vc-surface or --vc-accent, and switching the theme simply redefines those properties.

Light, dark or automatic

By default the theme follows the operating system (prefers-color-scheme). Set data-theme on <html> to force one:

<html lang="en" data-theme="dark">   <!-- or "light"; remove the attribute to follow the OS -->

With vici.js loaded, any button with data-vc-theme-toggle switches between light and dark and remembers the choice. It is a toggle button for the dark theme: give it a name such as “Dark theme” (as text or aria-label), and the script keeps aria-pressed in sync. Buttons with data-vc-theme-set="light", "dark" or "system" pick a theme directly; "system" returns control to the operating system.

.vc-when-light and .vc-when-dark show an element only in one page theme, which is how the toggle swaps its moon for a sun. From JavaScript: Vici.theme.set('dark'), Vici.theme.get(), and the vc:themechange event on document.

Theme islands

data-theme works on any element, so a single section can switch theme on its own: a dark hero on a light page, or a light card inside a dark dashboard.

Pastel sections

.vc-tint-merlot, -coral, -apricot, -honey, -sage, -teal, -fjord and -lilac paint a section in the palest step of a family. A tinted section is a light island: it stays pastel in both themes, and everything inside it uses the light-theme tokens, so text and components keep their contrast on a dark page.

What changes between themes

The light theme reads like paper: linen backgrounds, white cards, merlot ink and near-black merlot buttons. The dark theme turns the base colour into the canvas. Surfaces get lighter as they rise, primary buttons turn pastel blush with merlot text, and status backgrounds become deep shades of their family with pastel text. The full mapping is on Colour → Semantic tokens.

Override tokens

All of Vici lives in CSS cascade layers (vici.tokens, vici.base, vici.layout, vici.components, vici.utilities). Any CSS you write outside a layer wins automatically, so you never need !important.

/* Your stylesheet, loaded after vici.css */
:root {
  --vc-radius-md: 4px;              /* crisper buttons and inputs */
  --vc-font-display: 'Fraunces', serif;  /* swap the headline face */
}
/* a lilac primary in dark mode, whether it comes from the OS or from data-theme */
@media (prefers-color-scheme: dark) {
  :root:not([data-theme='light']) { --vc-accent: var(--vc-lilac-200); }
}
[data-theme='dark'] { --vc-accent: var(--vc-lilac-200); }
.vc-card { border-radius: 0; }      /* plain overrides just work */

Prefer semantic tokens

Use semantic tokens (--vc-text-muted, --vc-surface, --vc-danger-text) in your own CSS rather than primitives (--vc-neutral-700). Semantic tokens change with the theme; primitives do not.

Do 
.note { color: var(--vc-text-muted); }

Follows the theme and keeps its contrast in both themes.

Don't 
.note { color: #5b4b4e; }

Hard-coded colours disappear on the dark canvas and drift away from the palette.

Change the palette

The colour ramps are generated in OKLCH by scripts/palette.mjs. Edit the hue, chroma or anchor colours there, then run npm run palette. The build regenerates the CSS, the docs swatches and every export, and npm run check tells you straight away if a change breaks a contrast requirement.
